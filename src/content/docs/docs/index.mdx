**Self-hosted observability, from one container to an enterprise cluster.**

Obzly is an Apache 2.0 licensed, self-hosted observability platform for logs, traces, metrics and
dashboards. It speaks OTLP over gRPC and HTTP, so anything that can export OpenTelemetry (the
standard SDK for your language, or an OTel Collector in front of a database, web server or queue
you don't control) can send it data with no proprietary client library. Data is stored as
ZSTD-compressed Parquet, on local disk or on object storage such as S3. It also includes
[synthetic monitoring](/docs/how-to/synthetics/), which checks your endpoints from your own
locations, and an [infrastructure inventory](/docs/how-to/infrastructure/) built from what your
agents already send.

Obzly starts as a single app container (plus Postgres and Valkey) with no cluster to operate. The
same image runs each role on its own (`api`, `worker`, `broker`, `querier`, `control-plane`) when
your volume grows, so each part scales and fails independently. See [Architecture](/architecture/)
and [Features](/features/) for the bigger picture.

For a quick one-off from your own app, plain HTTP works too:

```bash
curl -X POST "http://YOUR_OBZLY_HOST/api/v1/logs/receiving/YOUR_PROJECT_ID" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{"logs": [{"level": "INFO", "message": "User logged in", "fields": {"user_id": "12345"}}]}'
```

## System requirements

The default single-container install needs a Linux host with at least **2 CPU cores, 4 GB of RAM
and 20 GB of disk**, plus Docker Engine 20.10+ and Docker Compose v2.0+. For Kubernetes, larger
volumes, and which parts can run on Spot nodes, see [System requirements](/docs/getting-started/requirements/).
