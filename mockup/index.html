    How it works

    OTLP in, Parquet on S3

    A batch is acknowledged only once the JetStream buffer has stored it. Workers write ZSTD Parquet to object storage, and queriers read it back with a warm cache.

    Logs

    Search a week of logs in seconds

    • Search by text and field, with a query builder or SQL and a field sidebar.
    • Live tail with cursor paging, so new arrivals don't shift the page you're reading.
    • Patterns and anomalies: new, spiking and dropping patterns against an earlier period.
    • Log context: the logs before and after any result, from the same pod or service.
    • Promoted fields: up to 12 per project become typed columns for fast filters and number ranges.
    • Wide searches read newest-first and stop once the page is full. Searching for an ID skips every segment whose bloom filter lacks it.

    Synthetics

    Know an endpoint is down before your users do

    • Checks: HTTP with assertions on status, latency, headers and JSON; TLS certificates (expiry, chain, protocol, self-signed allowed per monitor); TCP; DNS; ICMP.
    • Your own locations: obzly-probe runs as a Linux service, a container or a Helm release, inside your network or out on the internet.
    • Probe groups: several instances per location share the monitors. If one stops, the others take over within a minute.
    • Test runs an unsaved monitor from every location in seconds, with a timing waterfall from DNS to transfer.
    • Folders and dependencies: while a parent is down its children show Impacted and their alerts stay quiet, so an outage pages once.
    • Alerts per monitor through the shared channels: down, degraded, or a certificate about to expire.
    • YAML import and export with a preview, for reviewing monitors in git.

    Synthetics runs on a control plane. Results land in a Site project as ordinary metrics, so dashboards and PromQL work on them too.

    Infrastructure

    Every asset, its health and the reason

    • One inventory of clusters, nodes, hosts, namespaces, workloads, pods, containers and services, built every 5 minutes from data your agents already send.
    • Health with the reason: CPU, memory, disk, restarts, replicas, error logs and firing alerts.
    • Lifecycle and a change feed: new, not reporting, terminated, restarted.
    • Tree or table, with charts per asset and links straight into its logs, traces and dashboards.
    • Cloud connections add what runs no agent: load balancers, databases, buckets, functions and scaling groups from AWS accounts and Azure subscriptions. VMs and clusters join the hosts and clusters your agents report.
    • Read-only, keyless: a wizard writes the CloudFormation, Bicep or CLI. A probe group scans with its own identity, a role, or a federated token. Obzly stores identifiers only.
    • Cloud health: a full discovery every 4 hours and a health scan of what it found every 15 minutes: instance status checks, load balancer targets and Azure Resource Health.

    Architecture

    One image, five roles

    The single container is the smallest shape of one design. Set SERVICE_MODE and the same image runs each role on its own, so each part scales and fails independently.

    Durable ingest

    A batch is acknowledged only after the JetStream buffer has stored it on three replicas. Rows are searchable before they're written to Parquet.

    Backpressure

    When the buffer is full, clients get 429 or RESOURCE_EXHAUSTED and OTel Collectors retry.

    One owner per shard

    Leases give each ingest and compaction shard exactly one worker. Rolling updates drain readiness first.

    Storage layout

    Parquet is compacted in levels into hour-sorted files of one day each. A partitioned Postgres catalog keeps per-file statistics.

    Cache warmup

    Queriers keep their cache on a volume, pre-fetch each segment they own as it's uploaded, and warm up on start.

    Self-monitoring

    Every role serves Prometheus metrics on an internal port and traces its own requests into a system project.

    Inventory per Site

    A worker on each Site rebuilds the inventory every 5 minutes from data already stored. The control plane keeps none of it and merges the Sites in your browser.

    Alerts survive the control plane

    Sites fetch the shared channels and email relay every 5 minutes, sealed to their own key, and keep the last copy if the control plane is unreachable.
