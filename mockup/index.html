    How it works

    OTLP in, Parquet on S3

    A batch is acknowledged only once the JetStream buffer has stored it. Workers write ZSTD Parquet to object storage, and queriers read it back with a warm cache.

    Logs

    Search a week of logs in seconds

    • Search by text and field, with a query builder or SQL and a field sidebar.
    • Live tail with cursor paging, so new arrivals don't shift the page you're reading.
    • Patterns and anomalies: new, spiking and dropping patterns against an earlier period.
    • Log context: the logs before and after any result, from the same pod or service.
    • Promoted fields: up to 12 per project become typed columns for fast filters and number ranges.
    • Wide searches read newest-first and stop once the page is full. Searching for an ID skips every segment whose bloom filter lacks it.
    Search bar
    level:error service_name:api "timeout"
    Attribute names are PromQL-safe
    resource.k8s.pod.name  →  k8s_pod_name
system.cpu.time        →  system_cpu_time
    Traces

    Follow a request across services

    • OTLP traces over gRPC or HTTP, from any OpenTelemetry SDK.
    • Trace explorer and a service map built from real calls.
    • Jaeger-compatible query API: existing Jaeger clients work unmodified.
    • Tail sampling keeps whole traces, not random spans.
    • Zero-code traces on Kubernetes with OpenTelemetry eBPF Instrumentation (OBI).

    Metrics

    Keep Grafana, drop the metrics stack

    • PromQL-compatible API: point an existing Grafana Prometheus datasource at Obzly.

    Dashboards & Alerts

    Bring your dashboards, get paged quickly

    • Dashboards: build your own, or import Grafana or OpenObserve dashboard JSON.
    • Alert rules over metrics (PromQL), logs (counts of a search, optionally per field) or traces (count, errors, latency percentiles).
    • for durations, repeat intervals, labels and a live preview.
    • Notifications to webhooks, Slack, PagerDuty or email, through an outbox with retries and silences. About 15 seconds from rule to notification.
    • Incidents group error logs, failed spans and their shared traces.
    Example rule
    # Logs: count of a search
search:  level:error service_name:checkout
when:    count > 50
for:     5m
notify:  Slack, PagerDuty

    Architecture

    One image, five roles

    The single container is the smallest shape of one design. Set SERVICE_MODE and the same image runs each role on its own, so each part scales and fails independently.

    Scaling & HA

    Durable ingest

    A batch is acknowledged only after the JetStream buffer has stored it on three replicas. Rows are searchable before they're written to Parquet.

    Backpressure

    When the buffer is full, clients get 429 or RESOURCE_EXHAUSTED and OTel Collectors retry.

    One owner per shard

    Leases give each ingest and compaction shard exactly one worker. Rolling updates drain readiness first.

    Storage layout

    Parquet is compacted in levels into hour-sorted files of one day each. A partitioned Postgres catalog keeps per-file statistics.

    Cache warmup

    Queriers keep their cache on a volume, pre-fetch each segment they own as it's uploaded, and warm up on start.

    Self-monitoring

    Every role serves Prometheus metrics on an internal port and traces its own requests into a system project.
